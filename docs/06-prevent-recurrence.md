# 06 · 防复发：阻断指定程序启动

**简体中文** · [English](06-prevent-recurrence.en.md)

## 问题

清理是一次性的，但**重装是持续性的**。实测到的三条路径（详见 [04](04-why-hard-to-remove.md)）：

| 路径 | 触发条件 | 实测证据 |
|---|---|---|
| **客户端重装** | 阿里系客户端启动或更新时检查并重装 | 客户端目录内 `SafeGuard\` 检查器与安装包；日志 `7045` 记录了同一驱动服务的**多次**安装 |
| **SCM 自动恢复** | 服务崩溃后由服务控制管理器按策略重启 | 日志 `7031`：`...以下的修正操作将在 60000 毫秒内运行: 重新启动服务` |
| **看门狗回滚配置** | 常驻驱动监控自己的注册表配置并改回 | `AlibabaProtect` 的配套驱动内嵌 `CmRegisterCallback` |

**结论：只做一次性清理不够。** 本文讨论**如何在不修改任何客户端文件的前提下**，让这些执行体无法启动。

---

## 一、拦截对象（实测确定的 4 个）

| 映像名 | 角色 | 为什么必须拦 |
|---|---|---|
| `AlibabaProtect.exe` | 主进程 | 核心执行体 |
| `AliProtectUpdate.exe` | 更新器 | 会重新拉取并安装 |
| `AlibabaProtectCon.exe` | 检查器/连接器 | 由客户端触发时会尝试启动 |
| `pc-sdk-setup.exe` | 安装包（约 37 MB） | **真正执行安装动作的那个** |

> **上线前必做**：确认这 4 个名字在**你自己的机器上**没有同名第三方程序（全盘搜索）。IFEO 是**按文件名**全局生效的，误拦会影响无关程序。

## 二、方案对比（含实测结论）

| 方案 | 原理 | 优点 | 缺点 / 实测结论 |
|---|---|---|---|
| ⭐ **IFEO 映像拦截** | 按**映像文件名**把启动目标替换为不存在的路径 → `CreateProcess` 失败 | 纯注册表；**不改动目标文件**；**按名字全局生效**（多份副本一条规则全覆盖）；删键即还原 | 按**文件名**匹配（同名程序一并被拦）；调用方会收到启动失败 |
| 文件 ACL 拒执行 | 对 exe 设 Deny-Execute | 精确到文件 | ❌ **需要修改目标文件**（若目标位于他人客户端目录内，等于动了别人的程序） |
| 重命名 / 置 0 字节 | 让文件无法执行 | 直观 | ❌ 改了文件；且客户端更新会还原 |
| **服务注册表键加 Deny ACE** | 阻止服务被重新注册 | 理论上确定性 | ❌ **实测不可靠**，见第四节负面结果 |
| 预注册"占位服务" | 先占住服务名，使安装时返回 `ERROR_SERVICE_EXISTS` | 90 秒实测稳定存活 | ⚠️ 系统里会多一个**假服务条目**；若安装器"先删后建"则被绕过；**且 `sc create` 本身有误建风险，见 4.3** |
| Autoruns 禁用自启 | 关闭已知自启项 | 图形化、覆盖面广 | ⚠️ 只管**已知**项；安装器可创建全新条目 |
| 安全软件自定义规则 | 借安全软件拦截 | 有日志与告警 | ⚠️ 需 GUI 配置；依赖该软件自身 |

**选型逻辑**：目标是"**在不碰他人程序文件的前提下使其无法运行**"，因此 IFEO 是首选。

## 三、IFEO 原理

### 3.1 它本来是什么

Windows 内核在创建进程时，会按**映像文件名（不含路径）**查询：

```
HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\<文件名>
```

这是**给调试器用的官方机制**：在该位置写入 `Debugger` 值后，Windows 会改为启动那个调试器，并把原程序作为参数传给它（VS / WinDbg 的挂接调试即依赖此机制）。

### 3.2 怎么变成"拦截"

既然 `Debugger` 会**替换**真正的启动目标，那把 `Debugger` 指向一个**不存在的路径**，`CreateProcess` 就会因"找不到调试器程序"而**直接失败** —— 目标程序永远不会被执行。

```
HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\AlibabaProtect.exe
    Debugger = C:\Windows\System32\BLOCKED-By-Admin-No-Exec.exe     ← 该路径故意不存在
```

**关键特性**：

- **按映像名全局生效** —— 无论目标文件在哪个目录、有几份副本、客户端更新后换了路径，一条规则全部覆盖
- **调用方无法绕过** —— 无论谁发起（客户端、计划任务、用户双击），都在 `CreateProcess` 层面被拦
- **零文件改动** —— 不触碰被拦截程序所在的任何文件
- **秒级可逆** —— 删掉注册表键立刻恢复

## 四、实测：三种方案的验证结果

### 4.1 ⭐ IFEO —— 已验证有效

**不能只回读注册表**（那只能证明"值写进去了"），**必须做功能验证**。验证方法与完整记录见 [05-execution-forensics.md](05-execution-forensics.md)，摘要：

| 验证 | 结果 |
|---|---|
| 一次性探针（`IFEO_PROBE_TEST.exe`）：加拦截前执行 | ✅ 成功，`exit=0` |
| 同探针：加拦截后执行 | ✅ **`CreateProcess` 失败：系统找不到指定的文件** |
| 真实目标的 Prefetch 交叉验证 | ✅ 无 Prefetch 记录 + `LastAccessTime` = 触发时刻 ⇒ 被尝试但被拦住 |
| 清理后既有 4 条拦截 | ✅ 全部仍在，子键计数前后一致 |

### 4.2 ❌ 负面结果：服务注册表键加 Deny ACE —— 不可靠

社区有一种做法：**夺取服务注册表键所有权，然后给 `SYSTEM` 账户加 Deny ACE**（拒绝 `SetValue` / `CreateSubKey` / `Delete` / `ChangePermissions` / `TakeOwnership`），理由是"看门狗以 SYSTEM 权限回滚配置，所以必须连 SYSTEM 都拒绝"。

**实测结论：不可靠。**

| 步骤 | 结果 |
|---|---|
| 建键 + 加 SYSTEM Deny ACE | ✅ `sc.exe create <name>` 被拒：`CreateService 失败 5: 拒绝访问` |
| 90 秒观察（**不调用 `sc create`**） | ✅ 键与 ACE 稳定存活 |
| **调用 `sc create` 失败后** | ❌ **下次检查时该键已不存在**（3 次实验中 2 次复现） |

**推断**：**服务控制管理器在 `CreateService` 失败时会回滚，删除它正在创建的那个键** —— 由于该键已被预先创建，回滚把**我们预先放的拦截桩一并删掉了**。

**后果**：安装器**第一次尝试就会销毁这道防线**，第二次尝试即可成功。防线形同虚设。

### 4.3 ⚠️ 关于"预注册占位服务"的重要警告

上表中"预注册占位服务"（先建一个同名服务占位，使安装时返回 `ERROR_SERVICE_EXISTS`）看起来可行，**但它的验证过程本身有副作用，实测中因此误建了假服务**：

| 风险 | 说明 |
|---|---|
| **`sc create` 语法陷阱** | `binPath=` 等参数名**后面必须紧跟一个空格**（`binPath= "..."`，等号后有空格）。写成 `binPath="..."` 会被解析为服务名的一部分，**仍然创建服务**，只是参数错误 |
| **误建后必须清理** | 一旦建出假服务，**必须立即删除**，否则系统里会长期留一个指向错误路径的服务条目 |
| **误建记录** | 实测中因此**两次建出指向 `notepad.exe` 的假服务**（实验用），已清理并核验 |

**误建后的清理命令**：

```cmd
:: 先确认现状（是否真的被建出来了）
sc.exe query AlibabaProtect
sc.exe query AliPaladin
reg query "HKLM\SYSTEM\CurrentControlSet\Services\AlibabaProtect"
reg query "HKLM\SYSTEM\CurrentControlSet\Services\AliPaladin"

:: 若确实存在，立即删除
sc.exe delete AlibabaProtect
sc.exe delete AliPaladin
```

**核验干净的标准**：上述 4 条命令全部返回"服务不存在 / 找不到项"。

> ⚠️ **建议：不要使用"预注册占位服务"方案。** IFEO 已实测有效且无此副作用，没有理由引入这个风险。若你仍要尝试，**请先备份注册表，并在每次实验后立即执行上面的核验**。

### 4.4 ⚠️ 常见故障：写入被安全软件拦截（实测踩坑）

**症状**：`--apply` 或手工写注册表时报：

```
PermissionError: [WinError 5] 拒绝访问。
```

而**当前终端明明是管理员**（`IsUserAnAdmin = True`）。

**这是安全软件（HIPS）在对 `Image File Execution Options` 做写入保护**，与权限无关。

#### 怎么确认是它

做一次对照实验 —— **普通 HKLM 键能写、IFEO 子键不能写**，即可锁定：

| 测试目标 | 结果（实测） | 说明 |
|---|---|---|
| 普通 HKLM 键（如 `SOFTWARE\<临时名>`） | ✅ 可写 | 权限没问题 |
| **IFEO 下新建子键** | ❌ **拒绝访问** | ← 被保护 |
| 向**已存在**的 IFEO 子键写值 | ✅ 可写 | 保护只覆盖"新建子键" |

**注意最后一个**：保护只拦"新建子键"，所以已经建好的拦截**不会**被破坏 —— 但**新增/重建**会失败。这解释了"之前明明成功、后来突然失败"这种看起来矛盾的现象。

#### 处置

| 方案 | 说明 |
|---|---|
| 临时退出该安全软件，建立拦截后再开启 | 最简单；实测有效 |
| 在该安全软件的设置里为这个操作放行 | 更持久；位置因产品而异（通常在"HIPS / 自定义规则 / 注册表防护"） |
| 用 `reg.exe add` 代替 | **可能**绕过（不同产品拦截粒度不同），但不应依赖 |

> **顺带提醒**：这类"注册表防护"本身是有价值的功能（IFEO 正是常见的持久化手法）。**不要因为本指南就长期关闭它** —— 建立完拦截后应把它开回来。

> 本仓库的脚本在写入失败时**会抛异常并中止**，不会假报成功。若你看到 `[失败]`，先按本节排查。

## 五、局限

| 局限 | 说明 |
|---|---|
| **按文件名匹配** | 任何叫这个名字的程序都会被拦。上线前必须核实名字唯一性 |
| **拦不住"换名字的新安装器"** | 但通常"核心执行体"的名字是固定的 —— 拦住它即可 |
| **不作为安全边界** | 这是**运维层的稳定措施**，不是防攻击机制。有权限的进程可以删除该注册表键 |
| **用词注意** | IFEO 在攻击技术分类中被列为一种持久化手法（MITRE ATT&CK **T1546.012**）。本文用途是**阻止特定程序启动**，与攻击场景无关；对外表述时**避免使用"劫持/注入"字样**，用中性描述如"阻止指定映像名启动" |
| **需要管理员权限** | 写入 `HKLM` |
| **可能被客户端更新重置** | 实测到：客户端更新会把**计划任务的启用状态**改回（`Disabled` → `Ready`），需重新禁用。IFEO 条目本身在实测中未被清除，但这不构成保证 |

## 六、一个务实的组合

```
第 1 层：IFEO 拦截 4 个核心执行体（主进程 / 更新器 / 检查器 / 安装包）
第 2 层：禁用相关计划任务（AliProctectUpdate / AliUpdater）
第 3 层：每次客户端更新后，复查一次并复位被改动的条目
```

> 第 3 层是必要的 —— 实测确认客户端更新会重新启用被禁用的计划任务，**没有"设置一次永久有效"的方案**。

## 七、命令与还原

`scripts/ifeo_block.py` 把上述操作做成了可逆的双向命令：

```bash
# 建立 4 条拦截（需要管理员）
python scripts/ifeo_block.py --apply

# 查看当前状态
python scripts/ifeo_block.py --status

# 一键还原（只删本脚本建立的键）
python scripts/ifeo_block.py --remove
```

脚本**只写 `Image File Execution Options` 下的注册表键**，不触碰任何客户端文件；`--remove` 只删除目标为这些映像名的键，不会误删系统或第三方已有的 IFEO 配置。

**完全手工还原**（若你不想用脚本）：

```powershell
$ifeo = 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options'
foreach ($t in @('AlibabaProtect.exe','AliProtectUpdate.exe','AlibabaProtectCon.exe','pc-sdk-setup.exe')) {
    Remove-Item (Join-Path $ifeo $t) -Recurse -Force -ErrorAction SilentlyContinue
}
```
