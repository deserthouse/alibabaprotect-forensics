=== AliPaladin 服务注册项：与『文件系统微过滤器』相关的字段 ===

来源：服务注册表键导出 evidence/service-AliPaladin.reg
      位置：HKLM\SYSTEM\CurrentControlSet\Services\AliPaladin

意义：这是对 02 节『驱动注册了微过滤器』的【独立第二证据】——
      前者来自驱动二进制的代码（FltRegisterFilter），
      后者来自注册表里的运行期配置。

==========================================================================================
一、提取到的字段
==========================================================================================

  Type               = dword:00000002
  Start              = dword:00000002
  DisplayName        = "AliPaladin"
  Group              = "FSFilter Activity Monitor"
  Altitude           = "265109"
  Flags              = dword:00000000
  ImagePath          = hex(2):5c,00,3f,00,3f,00,5c,00,43,00,3a,00,5c,00,57,00,49,00,4e,00,
  DependOnService    = hex(7):46,00,6c,00,74,00,4d,00,67,00,72,00,00,00,00,00
  DefaultInstance    = "AliPaladin Instance"
  RunningFlag        = dword:00000001
  DriverActive       = dword:00000001
  OsSupportVer       = dword:00006658
  WorkStart          = dword:00000000
  Uplo               = dword:00000000

==========================================================================================
二、关键字段解读
==========================================================================================

  ⭐ Group = "FSFilter Activity Monitor"
     FSFilter 是 Windows 为【文件系统过滤驱动】保留的服务组。
     `Activity Monitor` 子组按加载顺序处于链路的【最上方】——
     即它能最先看到文件操作（观察者位置），这正是『监控/拦截文件活动』的典型挂载点。

  ⭐ Altitude = 265109
     Altitude（高度）是微过滤器的【唯一站位编号】，决定它在过滤栈中的确切位置。
     265109 落在微软为『活动监视器类』预留的高度区间内。
     ⇒ 高度值 + 组名共同确定：这是一个【真实的、会被加载的】微过滤器，
       而不是只在代码里出现过的空洞能力。

  ⭐ DependOnService = FltMgr
     依赖 FltMgr（Filter Manager，Windows 的过滤器管理器）。
     即：它必须由过滤器管理器加载 —— 这是微过滤器的【加载机制特征】，
     普通内核驱动不会依赖 FltMgr。

  · Type = 0x00000002  内核驱动
  · Start = 0x00000002 （自动启动）
  · Flags / RunningFlag / DriverActive 反映驱动的运行期标记位

==========================================================================================
三、结论
==========================================================================================

  两条独立证据一致：

    代码侧（.sys 内嵌函数名）      注册表侧（服务配置）
    ──────────────────────────    ────────────────────────────────
    FltRegisterFilter             Group = FSFilter Activity Monitor
    FltStartFiltering             Altitude = 265109
                                  DependOnService = FltMgr

  ⇒ 它是一个【已实际配置好站位、会被系统加载】的文件系统微过滤器。
  ⇒ 这解释了『删除安装目录报 Access denied』：文件操作在微过滤器层被拦截。

  仍属【配置能力】范畴：能确定的是『它具备并已配置拦截能力』，
  不能确定的是『它实际拦截了哪些具体路径』（需结合运行时观察，见 02 节局限）。
