=== 服务 AlibabaProtect 的 FailureActions（失败恢复策略）解码 ===

来源：服务注册表键导出 evidence/service-AlibabaProtect.reg
      位置：HKLM\SYSTEM\CurrentControlSet\Services\AlibabaProtect\FailureActions

为什么这条重要：它是『服务崩溃后自动复活』（见 04 节路径 B）的【注册表级证据】，
                与系统日志 7031 事件相互独立、彼此印证。

==========================================================================================
一、原始字节（共 44 字节）
==========================================================================================

  00 00 00 00 00 00 00 00 00 00 00 00 03 00 00 00 14 00 00 00 01 00 00 00 60 ea 00 00 01 00 00 00 60 ea 00 00 01 00 00 00 60 ea 00 00

==========================================================================================
二、按 4 字节小端解读为 DWORD（共 11 个）
==========================================================================================

  [ 0]  0x00000000  =  0        
  [ 1]  0x00000000  =  0        
  [ 2]  0x00000000  =  0        
  [ 3]  0x00000003  =  3        
  [ 4]  0x00000014  =  20       
  [ 5]  0x00000001  =  1        ← 1 = SC_ACTION_RESTART
  [ 6]  0x0000EA60  =  60000    ← 0xEA60 = 60000
  [ 7]  0x00000001  =  1        ← 1 = SC_ACTION_RESTART
  [ 8]  0x0000EA60  =  60000    ← 0xEA60 = 60000
  [ 9]  0x00000001  =  1        ← 1 = SC_ACTION_RESTART
  [10]  0x0000EA60  =  60000    ← 0xEA60 = 60000

==========================================================================================
三、可以确定的事实
==========================================================================================

  1) 该值存在且非全零 —— 说明配置了【失败恢复动作】。
  2) 其中出现 3 次数值 0x0000EA60 = 60000 —— 即【3 次、每次 60000 毫秒（60 秒）延迟】。
     出现位置：DWORD #6, #8, #10
  3) 其中出现 3 次数值 1 —— 枚举 SC_ACTION_* 中，1 = SC_ACTION_RESTART（重新启动服务）
     出现位置：DWORD #5, #7, #9
  4) 前三个 DWORD 为 0 —— 未设置『重启计算机提示信息』与『自定义命令』。

  ⇒ 综合：配置了 3 个『重新启动服务』动作，每个延迟 60000 毫秒。

==========================================================================================
四、与系统日志的交叉印证
==========================================================================================

  系统日志（Service Control Manager）实测原文：

    [id=7031] Alibaba PC Safe Service 服务意外地终止，这种情况已经出现了 1 次。
              以下的修正操作将在 60000 毫秒内运行: 重新启动服务。

  ⇔ 日志里的『60000 毫秒』『重新启动服务』，与本注册表值中的
     『0xEA60 = 60000』『3 次 SC_ACTION_RESTART』完全一致。

  ⭐ 两条独立证据（注册表配置 + 运行日志）指向同一结论：
     『结束进程』无效 —— 服务控制管理器会按该策略把它拉回来。

==========================================================================================
五、说明（证据卫生）
==========================================================================================

  · 本文件只陈述能确定的对应关系，不强行解释无法确证的头部字段偏移。
  · 该值为 SCM 写入的二进制结构（SERVICE_FAILURE_ACTIONS 家族），
    不同 Windows 版本的头部字段布局可能有差异；
    但『3 × 60000 毫秒 + 3 × SC_ACTION_RESTART』这一对应关系由数据本身直接给出。
  · 完整原始值保留在 service-AlibabaProtect.reg，读者可自行复核。
